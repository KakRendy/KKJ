Materi 1 · C2–C3

CIA Triad

CIA terdiri dari Confidentiality (kerahasiaan), Integrity (keutuhan), dan Availability (ketersediaan).

Confidentiality

Informasi hanya diakses pihak berwenang.

Contoh: pembatasan akses dokumen.

Integrity

Informasi akurat dan tidak diubah tanpa izin.

Contoh: hash verification.

Availability

Informasi/layanan tersedia saat dibutuhkan.

Contoh: backup dan recovery.

A. Integrity — Hash Verification

Tujuan: membuktikan perubahan input menghasilkan nilai hash berbeda. Hash digunakan untuk memeriksa integritas, bukan menyembunyikan data.

Tools: CyberChef. Cari operasi SHA2, pilih ukuran 256. Gunakan konfigurasi default lainnya; parameter round bukan pengaturan yang perlu diubah pada latihan SHA-256.

Eksperimen 1 — Text Integrity

  1. Buka CyberChef, cari SHA2 dan tambahkan ke Recipe.
  2. Pilih ukuran 256.
  3. Input: keamanankomputerjaringan.test.
  4. Catat hash pertama.
  5. Ubah satu karakter, misalnya huruf pertama menjadi kapital. Catat hash kedua.
  6. Kembalikan persis ke teks awal. Hash harus sama dengan hash pertama.
Hash SHA-256 teks asli:

addc70b2bf3e129ecf7fa09cf1d5a0fb5ef97141769599ac47569ea16c8dba79

Jika hasil berbeda, periksa spasi, huruf besar/kecil, tanda baca, dan karakter tersembunyi.

Eksperimen 2 — File Integrity

  1. Buat Data_Asli.txt berisi satu baris keamanankomputerjaringan.test.
  2. Gunakan Open File atau seret file ke Input CyberChef.
  3. Terapkan SHA2 ukuran 256 dan catat hash.
  4. Ubah isi file dengan satu karakter, simpan, lalu hitung ulang.
  5. Kembalikan isi file seperti semula dan pastikan hash kembali sama.
Checklist Integrity

B. Confidentiality & Availability — File Permissions dan Backup

Koreksi konsep: Read, Modify, dan Delete adalah permission/hak akses yang membantu mengendalikan akses dan perubahan. Availability diuji melalui backup dan recovery. Delete bukan prinsip Availability secara langsung.

Bagian 1 — Permission Windows

  1. Buat folder PRAKTIK_KEAMANAN dan file data_rahasia.txt berisi data dummy.
  2. Klik kanan file → Properties → Security.
  3. Pilih akun/grup yang tersedia. Amati Allow/Deny untuk Read, Write, Modify, dan Full control.
  4. Untuk melihat Delete secara lebih rinci: Security → Advanced → pilih principal → View/Edit permissions. Delete dapat menjadi permission tersendiri; Modify umumnya mencakup kemampuan mengubah dan menghapus file.
  5. Jangan mengubah permission akun sistem atau perangkat bersama tanpa arahan dosen.

Bagian 2 — Backup & Recovery

  1. Salin file ke subfolder BACKUP.
  2. Pastikan salinan dapat dibuka.
  3. Ubah nama atau pindahkan file utama sebagai simulasi kehilangan.
  4. Salin kembali dari BACKUP ke lokasi semula.
  5. Buka file hasil pemulihan dan pastikan isinya benar.
Checklist Confidentiality & Availability
Pertanyaan: Apa perbedaan Integrity dan Confidentiality? Mengapa backup mendukung Availability? Apakah hash yang sama membuktikan pengguna berwenang?
Materi 2 · C2–C4

AAA — Authentication, Authorization, Accounting

AAA menjawab tiga pertanyaan: siapa pengguna, apa yang boleh dilakukan, dan aktivitas apa yang tercatat.

KomponenPertanyaanContoh
Authentication (autentikasi)Siapa Anda?Login username/password, MFA.
Authorization (otorisasi)Apa yang boleh dilakukan?Viewer, Editor, Admin.
Accounting (pencatatan)Apa yang Anda lakukan?Audit log, waktu login, perubahan dokumen.
Pilih salah satu jalur praktik utama. Google Drive menunjukkan contoh layanan nyata; SIAKAD Lab menyajikan ketiga komponen AAA dalam satu skenario simulasi.

Opsi A — Google Drive

  1. Buat dokumen/folder dummy.
  2. Bagikan kepada akun rekan/akun latihan.
  3. Atur role Viewer, Commenter, atau Editor.
  4. Uji tindakan yang dapat dilakukan tiap role.
  5. Periksa Activity atau Version history jika tersedia.
Buka Google Drive

Detail aktivitas bergantung pada jenis akun dan pengaturan organisasi.

Opsi B — AAA Interactive Lab SIAKAD

Gunakan file AAA_Interactive_Lab_SIAKAD.html yang disediakan dosen.

  • Login benar dan salah.
  • Uji akses Admin, Dosen, dan Mahasiswa.
  • Amati tindakan yang diizinkan/ditolak.
  • Periksa audit log.
Akun dummy: admin01/admin123 · dosen01/dosen123 · mhs01/mhs123.

Threat–Vulnerability–Risk

IstilahArtiContoh
Asset (aset)Sesuatu bernilai yang perlu dilindungi.Database mahasiswa.
Threat (ancaman)Pihak/kejadian yang berpotensi merugikan.Phishing, malware, pencurian.
Vulnerability (kerentanan)Kelemahan yang dapat dimanfaatkan.Password lemah, software usang.
Risk (risiko)Kemungkinan peristiwa merugikan beserta dampaknya.Akun admin diambil alih dan data bocor.
Mitigation (mitigasi)Tindakan mengurangi kemungkinan/dampak.MFA, patching, backup.
Hubungan: Threat dapat memanfaatkan Vulnerability pada Asset dan menimbulkan Risk. Mitigation mengurangi likelihood atau impact.

Materi 4 · C2–C5

Security Controls — Kontrol Keamanan

Security Controls adalah kebijakan, prosedur, mekanisme teknis, atau pengamanan fisik untuk mencegah, mendeteksi, mengurangi, atau memulihkan dampak insiden.

Berdasarkan fungsi

JenisTujuanContoh
PreventiveMencegah insiden.Firewall, MFA, access control.
DeterrentMengurangi niat pelanggaran.Peringatan keamanan, kebijakan sanksi.
DetectiveMendeteksi aktivitas/insiden.IDS, monitoring, audit log.
CorrectiveMemperbaiki kondisi setelah insiden.Patching, menghapus malware.
RecoveryMemulihkan layanan/data.Restore backup, disaster recovery.
CompensatingKontrol alternatif saat kontrol utama belum tersedia.Pembatasan akses tambahan, monitoring ketat.

Berdasarkan sifat

JenisContoh
TechnicalFirewall, encryption, MFA, antivirus.
Administrative / ManagerialKebijakan keamanan, SOP, pelatihan.
PhysicalCCTV, kunci pintu, access card, penjagaan ruang server.
Satu kontrol dapat memiliki dua klasifikasi. Firewall merupakan kontrol Technical berdasarkan sifat dan umumnya Preventive berdasarkan fungsi.

Praktik kelas — CyberHub Firewall Configuration

Tujuan: menerapkan aturan firewall dan mengevaluasi trafik yang diizinkan atau ditolak.

Buka CyberHub Level 1 — Beginner Level 2 — Intermediate

Level 1 — Beginner

  1. Buka Firewall Configuration Level 1.
  2. Pelajari aturan awal dan kebutuhan jaringan.
  3. Ikuti instruksi membuat/memilih aturan.
  4. Uji trafik yang seharusnya diizinkan dan diblokir.
  5. Catat hasil dan alasan keputusan.
Fokus: Allow, Deny, source, destination, protocol, port.

Level 2 — Intermediate

  1. Buka Firewall Configuration Level 2.
  2. Analisis kebutuhan komunikasi.
  3. Susun aturan sesuai kebijakan.
  4. Uji beberapa kondisi trafik dan konflik urutan.
  5. Evaluasi aturan yang terlalu longgar/ketat.
Fokus: rule order, least privilege, evaluasi konfigurasi.

Prinsip firewall

  • Default deny: trafik ditolak kecuali ada aturan yang mengizinkan.
  • Least privilege: hanya izinkan komunikasi yang diperlukan.
  • Rule order: pada firewall ordered rules, urutan memengaruhi hasil.
  • Logging: catat aktivitas penting untuk monitoring dan investigasi.
Checklist Firewall
Pertanyaan: Apa risiko jika semua port dibuka? Mengapa firewall menerapkan least privilege? Bagaimana logging membantu evaluasi?

PR — CyberLab Security+ Simulator

PR difokuskan hanya pada Firewall Rule Builder. Fitur lain di simulator tidak wajib dikerjakan.

Individu Artikel Medium.com

Live Demo

Buka CyberLab Live Demo

Repository GitHub

Tujuan

  • Menerapkan aturan firewall dalam simulasi.
  • Memahami ordered ACLs dan first-match.
  • Menguji implicit deny.
  • Menganalisis pembatasan komunikasi jaringan.
  • Menjelaskan firewall sebagai preventive technical control.

Eksperimen wajib

1. Mengizinkan HTTPS
  1. Buka live demo dan Firewall Rule Builder.
  2. Identifikasi field rule yang tersedia.
  3. Buat/sesuaikan aturan mengizinkan HTTPS/TCP port 443 sesuai skenario yang tersedia.
  4. Jalankan pengujian dan catat hasil.
2. Membatasi SSH
  1. Buat aturan menolak SSH/TCP port 22 dari sumber tidak berwenang.
  2. Jika ada sumber tepercaya, bedakan akses tepercaya dan tidak tepercaya.
  3. Uji kedua kondisi dan dokumentasikan hasil.
3. Rule order dan implicit deny
  1. Amati pemrosesan aturan berdasarkan urutan.
  2. Uji aturan umum sebelum aturan spesifik jika simulator mendukungnya.
  3. Uji trafik yang tidak cocok dengan aturan Allow.
  4. Jelaskan pentingnya urutan rule dan default policy.
Penting: antarmuka simulator dapat berubah. Ikuti field yang benar-benar tersedia. Jika suatu skenario tidak didukung, jelaskan keterbatasannya dan gunakan pengujian yang tersedia. Jangan mengarang hasil.
